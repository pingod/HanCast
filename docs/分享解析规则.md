# 粘贴投屏 · 站点解析规则

粘贴一个链接/分享口令，HanCast 要把它变成电视能播的地址。
支持的站点不再写死在代码里：**内置规则一个站点一个模块**，
**外置规则是一段 JSON**，加站点不用改代码、不用重新打包、不用重启应用。

## 1. 解析管线（`hancast_sidecar/media/`）

```
粘贴文本 ── extract_candidates ──▶ 候选地址（已知平台优先，最多试 3 条）
   │
   ├─ ① url 阶段规则        拿到链接就能解析（B 站官方接口、外置 url 规则）
   ├─ 抓页面 / 展开短链
   ├─ ② url 阶段规则（重跑） 短链展开后落到某个负责的域
   ├─ 直链、HLS 播放列表判定
   ├─ ③ page 阶段规则       必须先见到正文（抖音分享页、外置声明式规则）
   └─ ④ 通用正文提取兜底     og:video / <video> / 内嵌 m3u8・mp4 / 相对流接口
```

规则「解析不出来」只让它让路，不会把一次本来能成功的粘贴判成失败；
交付前还会按电视视角检查裸拉能否成功，需要 Cookie/Referer 的自动改走本机代理。

## 2. 内置规则

| 规则 | 阶段 | 位置 |
| ---- | ---- | ---- |
| `bilibili` | `url` | `media/rules/bili.py`（委托 `BiliResolver`，反爬 Cookie 跨调用复用） |
| `douyin`   | `page` | `media/rules/douyin.py`（分享页内嵌 JSON 比通用正文提取可靠） |

新增内置站点 = 在 `media/rules/` 加一个模块、底部 `register(YourRule())`，
再到 `media/rules/__init__.py` 加一行 import。

## 3. 外置声明式规则

目录（首次解析粘贴时自动创建）：

- macOS `~/Library/Application Support/HanCast/share_rules/`
- Windows `%APPDATA%\HanCast\share_rules\`
- Linux `~/.config/hancast/share_rules/`

可在 `hancast_setting.json` 里写 `"share_rules_dir": "my_rules"`（相对路径按配置目录解析）
换到别处。目录内容变化按文件指纹检测，**下一次解析即生效，不用重启**。
外置规则 `priority=5`，先于内置规则命中；命中失败仍会回退内置与通用提取。

### 3.1 一条规则长什么样

采集站把播放地址塞在正文的 `player_aaaa` 里：

```json
{
  "name": "my-box",
  "hosts": ["box.example.net"],
  "path_regex": "^/play/",
  "stage": "page",
  "steps": [
    { "regex": "player_aaaa\\s*=\\s*(\\{.*?\\})", "as": "cfg" },
    { "json": "url", "from": "cfg", "as": "play" }
  ],
  "output": "{play}",
  "title_regex": "<title>([^<]+)</title>"
}
```

正文（`body`）在匹配前已归一化 `\/`、`\u002F`、`\u0026`、`&amp;`，
所以一条正则就能同时吃到 JS 转义与 HTML 实体的写法。

接口下发地址的站点（页面里只有一个 `/api/m3u8?origin=..&url=..`）：

```json
{
  "name": "api-vod",
  "hosts": ["vod.example.com"],
  "steps": [
    { "regex": "\"(\\/api\\/m3u8\\?[^\"]+)\"", "as": "api" },
    { "set": "{scheme}://{host}{api}", "as": "playlist" }
  ],
  "output": "{playlist}"
}
```

### 3.2 字段

| 字段 | 作用 |
| ---- | ---- |
| `name` | 日志与 `via` 字段里的规则名，缺省用文件名 |
| `hosts` | 主机名匹配列表（相等或子域） |
| `path_regex` | 可选，限定路径（`^/play/` 这类） |
| `stage` | `page`（默认，先抓正文）或 `url`（拿到链接就解析，不抓页面） |
| `enabled` | `false` 时整条跳过，便于临时停用 |
| `headers` | 可选，目前用于 `Referer` |
| `steps` | 顺序执行，最多 12 步，结果写进变量池 |
| `output` | 一条或一个列表；省略时自动从正文里找流地址（含 `&token=` 尾巴） |
| `title_regex` | 可选，取标题；缺省用 `<title>` / 主机名 |

步骤类型（值里的 `{name}` 用变量池插值，缺变量直接报错，绝不把半截模板当地址交出去）：

- `{"fetch": "{url}"}` —— 抓一个地址，更新 `base`（最终 URL）、`host`、`body`
- `{"regex": "...", "group": 1, "from": "body", "as": "cfg", "ignorecase": true}`
- `{"json": "data.list.0.url", "from": "cfg", "as": "play"}` —— `.` 分路径，取不到就报错换下一条规则
- `{"set": "https://api.example.com/vod?id={id}", "as": "api"}`

内置变量：`url`（命中的页面地址）、`host`、`scheme`、`path`、`base`、`body`。

### 3.3 排错

应用内「日志 → 媒体与链接解析」（模块前缀 `hancast.media`）会写清楚每一步：加载了几条外置规则、
哪条规则让了路及原因。规则文件不是合法 JSON 只跳过它自己，不影响其余站点。

现场复现：`python tools/share_resolve_probe.py --serve --play --mpv "<粘贴内容>"`
把真实解析管线跑一遍，再用系统 ffmpeg 与**打包版 mpv**各自实解一段；
站点被 WAF 挡住时可用 `--segment <分片地址> --referer <页面地址>` 只验代理与播放器。

## 4. 采集站的三类坑

采集/影视站（4kcz、厂长资源这类）不走接口，把真流地址藏在壳播放器里，
三类问题各自都要处理，缺一个就是「投不了屏」或「只响一声」。

**① 壳地址解包。** 播放页里的 `py.php?...&url=<真正的 m3u8>`，壳本身回 403，
永远跟不进去。解析器把查询串里 `url/src/playurl/m3u8/...` 这类键的值也当候选，
双重编码（`url=https%3A%2F%2F...`）先解一次再取，壳地址自己不参与试播。

**② 非 ASCII 地址。** 流的中文文件名与全角冒号直接出现在路径里（`/hls7/生化危机：爆发夜/1.ts`）。
`requests` 会用 latin-1 编码请求头，把这种 URL 当 `Referer` 时直接
`UnicodeEncodeError` —— 整条候选被当成异常丢弃。所有候选在进管线前统一
`_ascii_url()` 百分号编码（幂等，已编码的不会二次编码），域名走 IDNA。

**③ 披着图片皮的 TS 分片。** 站点把分片当「图片」传到免费 CDN
（`file.icve.com.cn/rc/…/xxxx.png`），前 61 字节是一段合法的 1×1 PNG，之后才是
188 字节对齐的 MPEG-TS。三层都会拒它：

- HLS 客户端按**分片 URL 的后缀**白名单放行（ffmpeg 8 `allowed_segment_extensions`、
  打包 mpv 内旧 ffmpeg 的 `allowed_extensions` → `blocked for security reasons`）。
  代理改写播放列表时把每条子地址登记成合规后缀（`.ts`/`.m3u8`，见 `player_safe_suffix`），
  并在 `_tv_can_fetch` 里判定「后缀播放器不认 → 改走本机代理」。
- 光换后缀不够：打包 mpv 会用有限 `analyzeduration` 探首块，看到 PNG 魔数就选 PNG
  解码器然后报 `error reading packet`。代理在转发前用同步字节对齐找出伪装头并剥掉，
  Content-Type 一并改成 `video/mp2t`，长度同步修正。
- 剥过头之后不能再宣称「这是从 0 开始的区间」，否则 ffmpeg 的 http.c 报
  `Unexpected offset: expected 0, got 61` 直接拒收 —— 伪装头只在文件头，
  所以只处理「无 Range / `bytes=0-`」的请求并按整条资源（200）应答，
  拖拽用的中段 Range 请求原样透传（那里没有伪装头）。

另外两条与防盗链有关的兜底：CDN 把「页面域的 Referer」当盗链特征拒 403
（`file.icve.com.cn`），代理带页面头被拒时改用裸 UA 重试一次，Range 原样保留；
macOS 上 `requests` 会继承系统代理（`127.0.0.1:9565`），代理端口一失效，
解析与代理转发都改直连重试，表现为「同一个链接昨天能投今天不能」被修掉。
