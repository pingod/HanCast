## 1. 目标场景与边界

**做什么**：把一部 Android 手机的实时屏幕，以**独立窗口**的形式弹在本机桌面上（手机 → 本机，电脑当接收端）。
窗口里的画面、触摸/键鼠回控、声音、横竖屏旋转都由 scrcpy 自己处理，HanCast 只负责「找到工具、找到设备、把窗口拉起来、用户关掉时收拾干净」。

**不做什么**（本版明确划界）：

- **不自研传输协议**。曾评估过让 scrcpy `--record=<FIFO>` 把 MKV 流交给自带 mpv 播放（`app/src/recorder.c` 的 `file:` 前缀意味着只能写文件/FIFO、不能直接 stdout；`Streamer.java` 的每包 12 字节头 + 4 字节 codec-id 的自研解析可行但风险高且无真机可验），结论是 v1 不做。
- **不内置 mpv 播放手机流**，也**不把镜像画面自动转投电视**。想投电视的用户可以起完镜像后，再用现有「屏幕投屏 → 窗口源」把那个 scrcpy 窗口抓去 HLS 分发（macOS 的 `ffmpeg_manager.py` 窗口枚举 `darwin_windows()` 能列到独立窗口）。两条链路在 v1 不自动串接。
- **不做 iPhone / iOS**。iOS 的屏幕镜像走 AirPlay 接收，是另一套东西。
- **不做 Miracast 接收**。macOS 没有 Wi-Fi Direct P2P，Android 的「无线投屏」多数走 Miracast，本机没法直接当 Miracast sink。

## 2. 为什么是 scrcpy

Android 屏幕镜像到桌面这条路上，唯一不依赖接收端协议栈、又能开箱即用的方案是 **ADB + scrcpy**：

- `adb` 负责设备发现/授权/端口转发；`scrcpy` 负责视频流（H.264/H.265）、音频转发（scrcpy ≥ 2.0）、窗口渲染与输入回控。
- 两者都是跨平台 CLI，macOS 上一个 `brew install scrcpy` + `brew install android-platform-tools` 就齐。
- HanCast 把「拉起一个外部 scrcpy 进程」当作唯一动作，**进程生命周期可控、可本机验证**——比内置播放器/自研协议的风险面小一个数量级。

## 3. 整条链路

```
 用户点「手机镜像」
        │
        ▼
 前端 MirrorPanel.vue ──invoke──► 壳层 lib.rs (6 条 mirror_ 命令)
        │                               │ stdin/stdout JSON
        │                               ▼
        │                     Sidecar commands.py ──► MirrorManager
        │                                               │
        │                             ┌─────────────────┼──────────────────┐
        │                             ▼                 ▼                  ▼
        │                        tools.py           manager.py         protocol_io
        │                     (定位 adb/scrcpy)  (拼参数 + Popen)   (emit_event)
        │                                               │
        │                                     外部 scrcpy 进程
        │                                     （独立窗口，画面/触摸/声音）
        │                                               │ 退出
        │                     ◄── mirror_state_changed ─┘（stdout 事件行）
        ▼
 前端 mirror store 收到事件 → 更新状态 / 发系统通知
```

关键代码位：
- 工具定位与设备枚举：`hancast-backend/hancast_sidecar/mirror/tools.py`
- 会话编排与进程管理：`hancast-backend/hancast_sidecar/mirror/manager.py`
- 命令注册：`hancast-backend/hancast_sidecar/commands.py` 的 6 条 `mirror_*`；壳层同名命令在 `src-tauri/src/lib.rs`
- 前端：`src/stores/mirror.ts`、`src/components/MirrorPanel.vue`、`src/types/mirror.ts`、`src/api/commands.ts` 的 6 个封装

## 4. 命令与事件契约

6 条命令（壳层与 Sidecar 同名，逐条对应关系见 [HanCast-Frontend-API.md](HanCast-Frontend-API.md) §7 #83-88）：

| 命令 | 入参 | 返回要点 |
| --- | --- | --- |
| `mirror_status` | `refresh?: bool` | `ok`、`platform`、`tools`（每项含 `key/found/path/version/source/error`）、`tools_found`、`install_commands`、`scrcpy_audio_supported`、`scrcpy_audio_min_version`，以及会话状态 `running/serial/model/started_at/pid/window/error/last_error` |
| `mirror_devices` | — | `{ ok, devices: [{serial, state, online, model, product, transport_id, wireless}], error? }` |
| `mirror_connect` | `address: "ip:port"` | `{ ok, address, error? }`（走 `adb connect`） |
| `mirror_start` | `{ serial, max_size, max_fps, video_bitrate, audio, control, turn_screen_off, stay_awake, always_on_top, window_title? }` | `{ ok, running, serial, pid, window: "external", error? }` |
| `mirror_stop` | — | 停止会话，`{ ok, running: false, stopped: bool }` |
| `mirror_set_tool_path` | `{ tool: "adb"\|"scrcpy", path: string }` | 保存手动路径（空串恢复自动检测）；错路径不静默回退 |

**事件** `mirror_state_changed`：载荷＝会话状态（`running`、`serial`、`model`、`started_at`、`pid`、`window`（恒为 `external`）、`error`、`ok`、`last_error`）。由 `manager.py` 的 `_emit()`（`manager.py:401`）在 scrcpy 进程退出时经 `protocol_io.emit_event` 发出。壳层 `sidecar.rs` 对所有非 `browser_request` 事件无条件 `app.emit` 转发，所以新增这条事件**不需要改 Rust 转发逻辑**。

## 5. scrcpy 参数拼装

`build_scrcpy_args(scrcpy_path, params, audio_supported=True)`（`manager.py:55`）把前端传的三档画质与开关翻成 scrcpy 命令行：

- `--serial <serial>`：目标设备（必填，缺失抛 `ValueError`）。
- `--max-size`（夹到 ≤ 4096）/ `--max-fps`（夹到 ≤ 240）：`0` 表示不传（用 scrcpy 原生分辨率/帧率）。
- `--video-bit-rate f"{n}M"`：码率（Mbps），同样有上限夹取。
- `--no-audio`：**仅当** scrcpy 支持音频（≥ 2.0.0）且用户关掉音频时才加。老版本 scrcpy 不支持音频相关参数，传了会报错，所以按 `audio_supported` 决定是否加，而不是无脑加 `--no-audio`。
- `--no-control`：只读镜像（不加回控）。
- `--turn-screen-off` / `--stay-awake` / `--always-on-top`：对应同名开关。
- `--window-title <标题>`：不带则用 scrcpy 默认。

## 6. 工具链定位与设备枚举

`tools.py` 对 `adb` / `scrcpy` 各做一次探测（`TOOLS = ("adb", "scrcpy")`）：

- **定位顺序**：用户手动指定（`mirror_adb_path` / `mirror_scrcpy_path`，见 `utils/config.py`）→ 平台常见目录（macOS `/opt/homebrew/bin`、`/usr/local/bin`、`~/Library/Android/sdk/platform-tools`、scrcpy.app；Windows `%LOCALAPPDATA%\Android\Sdk\platform-tools`、choco/scoop；Linux `/usr/bin`、`/usr/local/bin`、`/snap/bin`、`~/.local/bin`）→ 系统 PATH。
- **手填错不回退**：手动指定的路径若不存在/跑不起来，直接报错（`find_tool` 在 `tools.py:85`），**不悄悄退回自动检测**——否则用户以为自己填对了。
- **只有真跑得起来才算 found**：`tool_info`（`tools.py:157`）会真执行一次 `--version`，退出码 0 才标 `found: true`，否则带路径把 stderr 首行报出来。
- **30s 缓存**：探测结果缓存 30 秒，`refresh=true` 强制重测（`clear_cache` 在 `tools.py:225`）。
- **版本**：`parse_version` 抓 `scrcpy X` / `Android Debug Bridge version X`；`SCRCPY_AUDIO_MIN_VERSION = (2, 0, 0)` 决定 `scrcpy_audio_supported`。
- **安装指引**：`install_commands()`（`tools.py:186`）按平台给命令——macOS `brew install scrcpy` / `brew install android-platform-tools`；Windows `winget install Genymobile.scrcpy` / `winget install Google.PlatformTools`；Linux 按 `/etc/os-release` 给 pacman/dnf/apt。

**设备枚举**：`parse_adb_devices(text)`（`tools.py:229`）解析 `adb devices -l` 的输出——跳过 `*` 守护进程噪声行与 `List of devices attached` 表头；每行拆出 `serial/state/model/product/transport_id`，把 `model` 里的下划线还原成空格，`192.168.1.20:5555` 这类带端口的判为 `wireless: true`。`state` 是 `device`/`unauthorized`/`offline`，只有 `device` 才有 `online: true`；`mirror_start` 会据此给 unauthorized/offline 分别一句中文提示而不是干等。

## 7. 进程编排、回收与失败提示

`MirrorManager`（`hancast-backend/hancast_sidecar/mirror/manager.py:97-401`）的会话生命周期：

- **start**（`manager.py:208`）：先 `tool_status` 校验 adb/scrcpy 都在；校验 serial 与设备在线；用 `build_scrcpy_args` 拼参数；`Popen`（POSIX `start_new_session=True`，Windows `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`；stdin `DEVNULL`、stderr `PIPE`、stdout `DEVNULL`）；起一个读 stderr 的线程；再等 `_START_GRACE_SECONDS = 1.0` 秒宽限期（`manager.py:289`）——若 scrcpy 立刻退出，就把 stderr 末行当失败原因返回。已有会话在跑时直接报「已有镜像会话在进行中，请先停止」。
- **_watch**（`manager.py:382`）：等待进程退出，退出时 `_emit` 一条 `mirror_state_changed`；若**不是主动 stop** 且退出码非 0，把 stderr 末行写进 `last_error`（前端据此发系统通知）。
- **stop**（`manager.py:310`）：`terminate()` → `wait(_STOP_GRACE_SECONDS = 5.0)` → 超时 `kill()`；`_reset_locked` 清零状态。幂等。
- **cleanup**（`manager.py:339`）：`CommandHandler.cleanup()` 会调它，Sidecar 退出时确保子进程被收掉，不留孤儿。

**失败必须让用户看见**：`mirror_start` 的 invoke rejection 与 `mirror_state_changed` 里的 `error`，前端 mirror store 都在 `notify()` 里发一条系统通知（窗口收进托盘时也能看到），并做同错去重——与屏幕投屏/媒体投屏的失败出口约定一致（见 [AGENTS.md](../AGENTS.md) 安全约束第 5 条）。

## 8. 前端入口与交互

- **首页入口**：`src/views/HomeView.vue` 的 `.home__actions` 区，在「屏幕投屏」与「手机遥控」之间加一个「手机镜像」按钮（运行中显示绿点 + `home.mirrorRunning`），`@click="mirrorStore.openPanel()"`。
- **面板**：`src/components/MirrorPanel.vue`（`mp-*` 类名，`<Modal>` 内四区）——运行中状态 / 设备选择（`CustomSelect` + 刷新）/ 画质三列（尺寸·帧率·码率）/ 选项开关 / 无线调试折叠区（`adb connect`）/ 运行依赖区（缺工具时列 `install_commands` + 复制，每个工具一条手填路径 + 保存/清空）。actions 里「开始/停止镜像」按钮按 `canStart = toolsOk && !isRunning && selectedSerial && !starting` 置灰。
- **store**：`src/stores/mirror.ts`（setup store）。画质/选项偏好存 `localStorage 'hancast.mirror.settings'`（`PREFS_KEY`），逐字段兜底、deep watch 持久化。面板打开时 2s 轮询 `mirror_status`；`onMounted` 动态 import `@tauri-apps/api/event` 的 `listen` 订阅 `mirror_state_changed`，卸载时释放。
- **类型**：`src/types/mirror.ts`（`MirrorStatus` / `MirrorDevice` / `MirrorPrefs` / `MirrorStartParams` 等）。
- **i18n**：`src/locales/{zh-CN,en-US}.json` 的 `home.mirror*` 与 `mirror.*`（各 456 键）。

## 9. 边界、限制与后续

- **只在本机可用**：镜像窗口开在本机，不经局域网分发（scrcpy 走的是 adb 端口转发，不经 HTTP 服务端口）。
- **依赖外部工具**：adb 与 scrcpy 不在安装包里，需用户自装（面板给了安装命令与手填路径兜底）。缺工具时面板明确报「缺什么 + 怎么装」，不静默失败。
- **音频**：只有 scrcpy ≥ 2.0 才支持音频转发；老版本面板会把音频开关禁用并提示最低版本。
- **无线调试**：需先在手机开发者选项里开「无线调试」并配对，面板给 `adb connect ip:port` 的输入；首次配对（`adb pair`）当前不在 v1 面板里，需用户在终端完成，之后 connect 才成功。
- **⚠️ 真机未验**：本版没有真机 E2E。真机验收清单（建议下一步做）：① `brew install scrcpy android-platform-tools` 后 `mirror_status` 两条工具都 `found`；② 插线授权后 `mirror_devices` 列出在线设备；③ `mirror_start` 弹出 scrcpy 窗口、画面/触摸正常；④ 拔线 → 窗口关闭 → 前端收到 `mirror_state_changed` 且 `last_error` 有内容、系统通知弹出；⑤ `mirror_stop` 正常回收进程、无孤儿。
