## 1. 前置依赖

| 依赖 | 要求 | 用途 | 校验命令 |
| --- | --- | --- | --- |
| Node.js | ≥ 18（CI 用 20） | 前端与构建脚本 | `node -v` |
| Rust | 最新 stable | Tauri 壳层 | `rustc -V` |
| Python | ≥ 3.11（`.venv` 实为 3.12） | Sidecar | `hancast-backend/.venv/bin/python -V` |
| uv | 最新 | Sidecar 依赖与打包 | `uv --version` |
| mpv | 任意 | 接收投屏播放 | 见下方「资源目录」 |
| ffmpeg | **v2.3.11 起不再随包**，需带 `libx264` + HLS | 屏幕投屏 | 运行时由 `utils/ffmpeg_deps.py:189`（`status()`）检测：手动指定 → 系统已装 → 按需下载到 `<SETTING_DIR>/bin/`；根目录 `ffmpeg/` 已删除 |

安装依赖：

```bash
npm install
cd hancast-backend && uv sync --all-extras && cd ..
```

`--all-extras` 会带上 dev 组（`pytest`、`pytest-cov`、`nuitka`、`ordered-set`、`zstandard`，`pyproject.toml:32-37`）。

**资源目录（本地开发要手动准备，仓库不含二进制）**：

| 目录 | 内容 | gitignore 情况 |
| --- | --- | --- |
| `src-tauri/mpv/` | mpv 可执行文件（`bundle.resources` 的 `mpv/*` 指向这里，`tauri.conf.json`） | 二进制不入库，`portable_config/` 入库 |
| `mpv/portable_config/` | mpv 皮肤与设置（modernz） | 入库 |
| `src-tauri/hancast_sidecar/` | Sidecar 源码副本，由 `scripts/sync-sidecar.cjs:9-11` 同步过去供打包 | 生成物 |

放好后跑 `node scripts/check-resources.cjs` 确认每条 glob 都有命中（`tauri build` 不会替你检查，缺资源照样打出能装不能跑的包）。

## 2. 三条启动路径

### 2.1 全栈开发（最常用）

```bash
npm run tauri dev
```

Vite（端口 1420）+ Rust 壳层 + Python Sidecar 一起起。前端改 `.vue/.ts` 走 HMR；改 Rust 会重编壳层；改 Python **需要重启**（Sidecar 是子进程，dev 模式不会热重载）。

> `AGENTS.md` 早期写的是 `cargo tauri dev`（需要全局安装 Tauri CLI），仓库内的标准入口是 `npm run tauri dev`（`package.json:10` = `tauri`，走 devDependencies 的 `@tauri-apps/cli`）。该句已按 `package.json` 更正。

### 2.2 只写前端（浏览器 mock 模式）

```bash
npm run dev          # http://localhost:1420
```

`src/api/commands.ts` 在非 Tauri 环境下走 mock 分支：设备列表、设置、后台参数、规则包列表、失败台账、B 站多画质结果都是假数据（mock 清单见 [前端设计规格](HanCast-Frontend-Spec.md) §10）。**能用 UI 调的**：布局、样式、主题、i18n、画质切换交互、插件管理列表。**调不了的**：真实 SSDP/DLNA、mpv 播放、屏幕采集、剪贴板（浏览器权限模型不同）、开机自启。

### 2.3 只调 Sidecar（不装壳层也能测协议）

```bash
cd hancast-backend

# 逐行 JSON 模式（等价于壳层喂 stdin）
uv run python -m hancast_sidecar.main

# 持续运行模式：自动扫描设备、当渲染端，方便用手机投屏到本机试
uv run python scripts/run_sidecar.py
```

`run_sidecar.py:1-6` 的定位就是「手机投屏到本机」的手工验证；它会打印测试步骤。

手工喂一条命令：

```bash
cd hancast-backend && uv run python -m hancast_sidecar.main <<'EOF'
{"id":1,"cmd":"get_devices","params":{}}
{"id":2,"cmd":"exit","params":{}}
EOF
```

## 3. 改完代码怎么生效

| 改了什么 | 生效方式 | 注意 |
| --- | --- | --- |
| `src/**` | HMR 自动 | 类型检查靠 `npm run build`（`vue-tsc && vite build`，`package.json:11`） |
| `src/api/commands.ts` 加了新命令 | 还要在 `src-tauri/src/lib.rs` 加 `#[tauri::command]` 并**注册进 `generate_handler!`**（`lib.rs:1373-1440`），Sidecar 侧再进 `commands.py:110-197` 注册表 | 三层缺一层就是「前端调用报 no command / Sidecar 报 unknown cmd」 |
| `src-tauri/**` | 重编（dev 自动，约 1-3 分钟） | 见 §10 的 `cargo check` 桩 |
| `hancast-backend/**`（源码模式） | 重启 dev 或重启 Sidecar | 打包版另需 `npm run build:sidecar` |
| `rule-packs/**` | 改源码后 `python tools/build-rule-packs.py` 重打 zip，再在设置页「检查规则包更新」或直接导入 zip | 沙箱跑的是 zip 里的 `main.js`，不是 `rule-packs/` 源码 |
| `src/locales/*.json` | HMR 自动 | 两个语言文件必须**等键**（§5.4） |

## 4. 静态检查与本地校验

```bash
npm run build                     # vue-tsc + vite build，前端唯一门禁
cd hancast-backend && uv run pytest tests/test_imports.py   # 后端「能不能 import」的哨兵
node scripts/check-version.cjs    # 版本四处一致性（见 §9）
node scripts/check-resources.cjs  # bundle.resources 每条 glob 是否命中
bash tools/rust-check.sh          # 壳层 cargo check（带本地所需桩）
```

`tools/rust-check.sh` 存在的原因：干净的 `cargo check` 会因缺 mpv/sidecar 二进制资源而失败，脚本补齐了本地检查所需的最小桩（提交 `f38a2fd` 那条修复记录了完整前置）。

### 5.2 跑法

```bash
cd hancast-backend
uv run pytest tests/test_quality_switch.py -v --tb=short        # 定向（默认姿势）
uv run pytest tests/test_screencast.py -k "loopback" -v          # 按用例名筛
uv run pytest                                                    # 全量：只在发版前跑一次
uv run pytest --cov=hancast_sidecar --cov-report=term-missing    # 带覆盖率
```

**默认跑定向用例，不要动辄全量**：全量要起一堆 socket/线程，慢且噪音大；发版前才跑一次完整套（提交信息里的「134 个定向用例通过」就是这个口径）。

### 5.3 行为契约优先看测试

改协议前先把对应测试读一遍——测试是行为契约的最准记录，例如停止链路的「如实回报电视未确认停止」写在 `test_stop_cast_delivery.py`，静默下线摘除时序写在 `test_ssdp_discovery_retry.py`，规则包 zip 拒收条件写在 `test_jsplugins.py`。真机类结论则记在 `tools/` 的验收脚本里（索引见 [tools/README.md](../tools/README.md)）。

smoke 脚本需要真实环境（采集/ffmpeg），不要塞进 CI：

```bash
cd hancast-backend && uv run python tests/smoke_screencast.py
```

### 5.4 前端与 i18n

前端没有测试框架（`package.json` 里没有 `test` 脚本；`AGENTS.md` 早期把它写成待实现的 TODO，现已按现状更正），门禁就是 `npm run build` 通过（`vue-tsc` 类型检查）+ 真机点一遍。

i18n 必须等键，`zh-CN.json` 与 `en-US.json` 当前各 278 键。拍平比对：

```bash
node -e "
const a=require('./src/locales/zh-CN.json'),b=require('./src/locales/en-US.json');
const fl=(o,p='')=>Object.entries(o).flatMap(([k,v])=>typeof v==='object'?fl(v,p+k+'.'):[p+k]);
const A=new Set(fl(a)),B=new Set(fl(b));
console.log('zh-only',[...A].filter(x=>!B.has(x)),'en-only',[...B].filter(x=>!A.has(x)),'count',A.size,B.size)"
```

加 key 的规则：**两个文件同时加**，且不要在组件里硬编码中文（现存违规点见 [前端设计规格](HanCast-Frontend-Spec.md) 的 i18n 一节）。

## 6. 调试与取证

### 6.1 日志

| 平台 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\HanCast\logs\hancast.log` |
| macOS | `~/Library/Application Support/HanCast/logs/hancast.log` |
| Linux | `~/.config/hancast/logs/hancast.log` |

`logger.py:19-26`（路径）、`logger.py:33-37`（5MB × 3 轮转）。应用内入口：设置页日志面板 → `get_logs`（按模块前缀过滤，如 `hancast.guard`）、`set_log_level` 临时提级、`export_logs` 落盘拷贝（壳层弹保存框，`lib.rs:802-821`）。

**注意 dev 与打包版的差异**：dev 模式的 Sidecar stdout/stderr 打在 `npm run tauri dev` 终端里；打包版只有日志文件，别拿 dev 日志判断产物行为。

### 6.2 常用取证脚本

```bash
python tools/ssdp_probe.py                    # 抓组播/广播通告，看设备到底有没有出现
python tools/verify-ssdp-offline-eviction.py  # 静默下线摘除时序（需替身设备）
python tools/verify-dlna-stop-chain.py        # Stop 动作链路是否真到达设备
python tools/share_resolve_probe.py <链接>     # 单条链接走完整解析管线
python tools/verify-rule-packs-live.py        # 官方索引与 zip 是否可拉
node  tools/verify-params-ui.mjs              # 后台参数表与 params.py 逐键比对
bash  tools/accept-macos-artifact.sh          # 打包产物级验收
```

完整索引（含哪些需要真机/Windows 测试机/代理）见 [tools/README.md](../tools/README.md)。**修 bug 前先跑对应脚本复现，修完再跑它证明**——不接受「手工打补丁后看起来好了」。

### 6.3 局域网不通的定位顺序

1. 本机有没有绑上选定网卡（`list_network_interfaces` → `config.network_interface`）；
2. 日志里 SSDP 发送失败行的 `errno`（`ssdp.py` 会带 errno 去重告警）；
3. macOS 打包版检查「本地网络」权限与 `NSBonjourServices` 声明（v2.2.12/v2.2.14）；
4. 请求有没有被系统代理吞掉（链路内 HTTP 必须绕代理，见 [故障排查](故障排查.md)）。

### 6.4 真机验证的边界

本机没有 Android SDK，**不要尝试 `flutter build apk`**（本项目也没有移动端代码）。涉及 Windows 行为的验收在局域网那台测试机上做（产物装好后看它的日志目录），macOS 的 `adb` 只能连设备不能注入触摸。

## 7. 新增一条能力的同步清单

以「加一个投屏控制命令」为例，缺一个就会在某一层静默失败：

1. **Sidecar**：`commands.py` 写 handler → 进注册表（`commands.py:110-197`）→ 返回值保持 JSON 可序列化；需要可调就登记 `params.py:35` 的 `PARAM_SPECS`（不要新配置键）。
2. **壳层**：`lib.rs` 加 `#[tauri::command]` 并注册进 `generate_handler!`（`lib.rs:1373`）；参数名用 camelCase 入、snake_case 转给 Sidecar（对照既有命令的写法）。
3. **前端**：`src/api/commands.ts` 加封装 + 返回类型 → `src/types/*.ts` 补类型 → store 调用；浏览器 mock 分支给一份假数据，否则 `npm run dev` 直接报错。
4. **事件**（若有）：Python 侧**只能**用 `protocol_io.emit_event`（stdout 单写者，`protocol_io.py:25`）；壳层无需改动即可转发（`sidecar.rs:345-368`）；前端 store 用 `await import('@tauri-apps/api/event')` 订阅并收集 `UnlistenFn`。
5. **i18n**：`zh-CN.json` + `en-US.json` 同步加键；UI 上的新模式要在界面里给出解释性文案，不能只有 toast。
6. **测试**：`hancast-backend/tests/` 加用例（协议/边界优先），或 `tools/` 加验收脚本。
7. **文档**：改了什么就同步什么——命令表进 [HanCast-Frontend-API.md](HanCast-Frontend-API.md)、组件/store 进 [HanCast-Frontend-Spec.md](HanCast-Frontend-Spec.md)、后台参数进 [架构总览.md](架构总览.md) §6、子系统行为进对应专文、`CHANGELOG.md` 记一条。见 §11。

## 8. 代码风格与项目约定

| 层 | 约定 |
| --- | --- |
| Python | PEP 8 + type hints；`dataclass` 定义数据；日志统一 `logging`（logger 名 `hancast.<模块>`，供 `get_logs` 前缀过滤）；注释写「为什么」，尤其是踩过的坑（`main.py:21-25`、`protocol_io.py:8-17` 是范例） |
| Rust | `rustfmt` 默认；命令层薄——业务在 Sidecar，壳层只做系统能力与转发 |
| 前端 | Vue 3 Composition API + TS；Pinia 管状态；主题靠 CSS 变量（`src/styles/variables.css`）；组件优先复用 `Modal.vue` / `CustomSelect.vue` |
| 通用 | 常量与可调项进登记表（`params.py`），不散落硬编码；跨模块身份/UA 只从 `utils/identity.py` 取 |

**安全约束的现实版本**（`AGENTS.md` 里那句「本地服务仅监听 127.0.0.1」已于 2026-10-15 按代码更正，见其「安全约束」第 3 条）：DLNA 描述服务器、媒体服务器、屏幕投屏 HLS 分发都**必须绑 `0.0.0.0`** 才能被局域网设备访问（`protocol/server.py:332`、`media/server.py:631`）。真正的边界是：

- 陌生设备投到本机 → 走投屏确认（[投屏确认.md](投屏确认.md)）；
- SOAP 请求体有大小上限（`media.max_soap_body_kb`）；
- 只有链路内必要的描述/来源抓取绕开系统代理，且不外发用户粘过的链接（失败台账只写本机配置目录，`media/failures.py`）。

## 9. Git 与分支约定

- 日常分支 `feat/<主题>`，`main` 是发布线；官方规则包索引与产物在 **main 的 raw 路径**上，改动 `rule-packs/` 后要合进 main 才能被用户拉到（[rule-packs/README.md](../rule-packs/README.md) §4）。
- 推 main 被拒多半是本地 main 落后，`git push origin HEAD:main`。
- **一个版本一笔发布提交**：一轮功能收在一笔 `feat(...)` + 版本 bump 里，提交信息带全版本契约；验收要在打 tag **之前**做完。
- 版本只能走 `npm run version:set <x.y.z>`（同步 `tauri.conf.json`、`package.json`、`Cargo.toml`、`pyproject.toml`，并由 `check-version.cjs` 把关）；手写某处版本会被滞后闸门拦下。
- 同一工作区可能被多个会话共用：**动手发布前先 `git status`/`git log` 看当前分支与别人在飞的东西**，别人在发版就不另起发布线。

## 10. 环境陷阱清单

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| `cargo check` 报缺资源 | mpv/sidecar 副本没放 | 用 `bash tools/rust-check.sh` |
| 装依赖后 electron/Nuitka 产物诡异坏包 | `extract-zip` 在 Node 26 下解包损坏 | 走系统 `unzip`，校验 `require('electron')` 之类装载 |
| 中文响应变成 `success:false`（ascii codec） | stdio 没强制 UTF-8 | 只在 `main.py:26-28` 这一处包，且早于 logger |
| 改完参数设置页读不到 | 打包版刷的是 bundle 内 `config.py` | 看 [构建与发布.md](构建与发布.md) §1.4 的 prebuild 行为 |
| 请求发到局域网却整体超时 | 系统代理（GFW 代理）劫持 | 链路内 HTTP 显式清代理；验证走 `HTTPS_PROXY=127.0.0.1:9565` 与否两种姿势都试 |
| 重启后 TCC 授权又失效 | adhoc 签名每版换身份 | 见 [屏幕投屏.md](屏幕投屏.md) 的平台限制节 |
| `pkill -f sidecar` 把开发中的东西打断 | Sidecar 是壳层唯一子进程入口 | 别 pkill；要重启就重启 dev |

## 11. 文档维护约定

这份文档集的目标是「读代码之前先读对的东西」，规则很简单：

1. **改代码的那一笔里同步改文档**，不留「以后再补」——历史证明以后不会补（`docs/Macast-*.md` 停更 3 个月，期间发了 32 个 tag）。
2. 每条关键论断挂 `文件:行号`；行号会漂，所以**每次大改后重跑引用校验**：

   ```bash
   python3 - <<'EOF'
   import re,os,collections
   idx=collections.defaultdict(list)
   skip={'.git','node_modules','.venv','__pycache__','target','dist','.pytest_cache','build'}
   for root,dirs,files in os.walk('.'):
       dirs[:]=[d for d in dirs if d not in skip]
       for fn in files:
           if fn.endswith(('.py','.rs','.ts','.vue','.json','.toml','.cjs','.js','.css','.html','.xml','.md')):
               try: idx[fn].append((os.path.join(root,fn),sum(1 for _ in open(os.path.join(root,fn),encoding='utf-8',errors='replace'))))
               except Exception: pass
   bad=0;tot=0
   pat=re.compile(r'`([^`\s/]*?\.(?:py|rs|ts|vue|json|toml|cjs|js|css|html|xml|md)):(\d+(?:-\d+)?)`')
   for d in ['README.md','README_en.md','CHANGELOG.md','docs/README.md','tools/README.md','rule-packs/README.md']+[f'docs/{f}' for f in os.listdir('docs') if f.endswith('.md')]:
       for m in pat.finditer(open(d,encoding='utf-8').read()):
           f,ln=m.group(1),m.group(2); tot+=1
           hi=int(ln.split('-')[-1]); c=idx.get(f,[])
           if not c or not any(n>=hi for _,n in c):
               bad+=1; print('STALE',d,f+':'+ln)
   print(f'{tot} refs, {bad} stale')
   EOF
   ```

   它只做「文件存在 + 行号不越界」的机械检查，能抓住复制粘贴出来的假引用；语义是否还成立要人读。
3. 过时但不删的内容：**标为历史**（像 [HanCast-Backend-Spec.md](HanCast-Backend-Spec.md) 那样写清「2.0 设计稿，现状以架构总览为准」），不要假装它还描述现状。
4. 每份 `docs/*.md` 头部带 `最后校对：<日期>，对应版本 v<x.y.z>`，让「多久没更新」一眼可见。
