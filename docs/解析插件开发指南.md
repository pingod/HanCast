# 解析插件开发指南（JS 规则包）

设置页「解析插件」导入一个 ZIP，就能让某个网站的链接/分享口令被解析成电视可播的地址。
规则用 JavaScript 写，跑在 sidecar 内置的 QuickJS 沙箱里；**导入即生效、覆盖导入即更新、
改动不用重启应用**。适合：接口带签名/加密参数、页面结构用声明式正则说不清、
或者想复用一套脚本逻辑拆多个函数的场景。简单站点优先用
[声明式 JSON 规则](分享解析规则.md)，够用就不必上 JS。

**程序里没有任何编译进去的站点规则**：一个包都没装的干净安装，B 站和抖音的链接就是解析不
了——这是产品契约，不是 bug。官方包（`hancast-template`、`hancast-bilibili`、
`hancast-douyin`）住在仓库根 `rule-packs/`，打成 zip 连同索引发布在公开仓库里，
**不随应用出货**；用户装不装、装哪个，由设置页「检查规则包更新」决定，机制见 §6、§7。

## 1. 插件包长什么样

ZIP 里**恰好一个 `manifest.json`** + 若干 `.js`（可带一层目录，导入时拍平）：

```
my-plugin.zip
├── manifest.json
└── main.js
```

`manifest.json`：

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "author": "you",
  "description": "一句话说明这个插件解析什么站",
  "scripts": ["main.js"]
}
```

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `name` | ✓ | 插件标识，只允许字母/数字/下划线/连字符（1-64 字符）；同名导入=覆盖更新 |
| `version` | | 显示在设置页；「检查规则包更新」靠它决定给不给你升级（见 §6） |
| `author` / `description` | | 显示在设置页；`description` 也会进官方索引 |
| `update_url` | | 这个包自己的 zip 下载地址；索引里没有它时 `pull` 退回用它（见 §6） |
| `scripts` | ✓* | 要加载的 .js 文件名列表（相对包根，不能带路径）；`main` 是旧写法，二者都没有时按文件名排序加载包内全部 .js |

`main.js` 里用 `registerRule` 声明规则，一个脚本可以声明多条：

```js
registerRule({
  id: 'main',            // 可选；停用状态按它记忆，缺省用 name
  name: 'main',          // 必填，日志与 via 里显示
  hosts: ['example.com', 'www.example.com'],   // 必填，主机名（相等或子域匹配）
  stage: 'page',         // 'page'（默认，先抓正文再调你）或 'url'（拿到链接就调你）
  priority: 5,           // 可选 4-8，缺省 5；数字小的先试
  resolve: function (ctx) {
    // ……解析逻辑……
    return { url: 'https://cdn.example/video.m3u8', title: '标题' }
  }
})
```

`hosts` 没命中的链接轮不到你；命中后 resolve 抛错/返回 null/返回的地址不是 http(s)，
都只是「这条规则让路」，解析管线继续走其余规则包规则、声明式规则和通用正文提取，
不会把粘贴判成失败。

## 2. resolve(ctx)：入参与返回值

`ctx` 字段（与声明式规则拿到的同一份视图）：

| 字段 | 说明 |
| ---- | ---- |
| `url` | 本次要解析的地址 |
| `base` | 同 `url`（跟随跳转后的最终地址会通过宿主函数的 `finalUrl` 拿） |
| `host` / `scheme` / `path` | 拆好的地址成分，host 已小写 |
| `body` | `page` 阶段才有：已归一化 `\/`、`\u002F`、`&amp;` 的正文；`url` 阶段是空串 |

返回值三选一：

- **字符串**：就是播放地址，等价 `{url: …}`；
- **`{url, title?, headers?, base?, thumbnail?}`**：`headers` 里放播放需要的请求头（`Referer`、
  签名头这类），会随代理下发；`base` 作为验证/代理用的 Referer 来源，缺省用命中页地址；
  `thumbnail` 是封面图地址（相对地址按 `base` 补全），设置页与投屏列表会显示；
- **`null` / 抛错**：让路。

地址支持相对路径，宿主会按 `url` 补全成绝对地址。交付前解析器仍会按电视视角
（裸 UA、无 Cookie）验证一次，验证不过自动改走本机代理——插件不用自己关心防盗链。

## 3. 宿主 API（`host.*` 与内置函数）

沙箱里没有 `fetch`/`XMLHttpRequest`/`setTimeout`/任何 IO，一切能力经宿主注入。
网络函数共用解析会话（Cookie 跨调用延续），单请求超时不超过 15 秒、正文截到 4MB，
且全部计入这次解析的总时长预算——**不要在 resolve 里写轮询或下载大文件**。

### 3.1 网络（options 是可选对象）

| 函数 | 返回 | 说明 |
| ---- | ---- | ---- |
| `host.getString(u, o?)` | 文本 | 非 2xx 抛错 |
| `host.getHtml(u, o?)` | 文本 | getString + 归一化（与 `ctx.body` 同一视图） |
| `host.getJson(u, o?)` | 对象 | getString + `parseJson`，容忍 JSONP |
| `host.fetch(u, o?)` | `{status, finalUrl, body}` | 非 2xx 不抛错，自己判 |
| `host.finalUrl(u, o?)` | 字符串 | 跟完重定向的最终地址（HEAD/GET，不读正文） |
| `host.status(u, o?)` | 数字 | 只看状态码 |

`options` 字段：

| 字段 | 说明 |
| ---- | ---- |
| `mobile` | `true` 用手机 UA；缺省桌面 UA（分享页类站点常要手机 UA 才给完整内嵌 JSON） |
| `referer` | 请求带 Referer |
| `headers` | `{名: 值}`，逐条并入请求头（优先于上面两项） |
| `method` | GET（默认）/ POST / HEAD / PUT |
| `body` | 字符串，POST/PUT 的请求体 |

### 3.2 HTML

`host.select(html, css, baseUrl)` → 节点数组（最多 200 个）：

```js
host.select(ctx.body, 'div.playlist a', ctx.url)
// [{ tag: 'a', text: '第1集', attrs: {href: '…'}, abs: {href: '绝对地址'}, html: '…' }]
```

`abs.href` / `abs.src` 已按 `baseUrl` 补成绝对地址。

### 3.3 存储与配置

| 函数 | 说明 |
| ---- | ---- |
| `host.readCache(name)` | 读插件私有缓存，不存在返回 `''`；name 只取文件名部分 |
| `host.writeCache(name, text)` | 写缓存（上限 4MB），比如缓存接口 token |
| `host.cacheAge(name)` | 缓存 age 毫秒数，不存在返回 -1 |
| `host.getPref(key, def?)` / `host.setPref(key, value)` | 插件私有 KV，落 `state.json`，重装插件不丢 |

### 3.4 工具

`host.md5(t)`、`host.sha256(t)`、`host.base64Encode(t)`、`host.base64Decode(t)`、
`host.htmlDecode(t)`（HTML 实体）、`host.userAgent(desktop?)`、
`host.sleep(ms)`（受解析预算约束）、`host.log(msg)`（进「媒体与链接解析」日志）。

数据取值（全局函数，不用挂 host）：`at(obj, 'a.b.0.c')`（`.` 路径，负数下标从尾数）、
`str/int(obj, path, def?)`、`items(obj, path)`（保证给数组）、
`regexInt(text, /re/, def?)`、`parseJson(text)`（容忍 JSONP）、
`absUrl(baseUrl, u)`。

## 4. 运行边界（为什么有些写法不行）

- **内存 64MB / 死循环看门狗**：纯 JS 卡死只废掉这一次调用（超时让路），脚本线程
  不再复用——写代码不必省内存，但别指望 `while(true)` 轮询。
- **时间预算**：宿主网络函数的超时直接挂解析总预算（默认约 25 秒），resolve 里
  发起的三五个请求是常态，二三十个就会把预算吃穿。
- **只允许 http(s)**：宿主网络函数对其他 scheme 一律抛错。
- **脚本报错不影响别人**：一个插件崩了只标记它自己（设置页显示「加载失败」+ 原因），
  其余插件与声明式规则照常。

## 5. 安装与管理（用户视角）

- 设置 → 解析插件 →「导入 ZIP」选本地 zip，或在同排输入框里填地址点「从 URL 导入」
  （页面上没有拖拽区，别指望把文件拖进去）；
- 不想自己找 zip 就在同页「规则包更新」段点「检查规则包更新」（Tauri command
  `plugin_check_updates`）：拿后台参数 `rules.index_url` 指向的索引跟本机对一遍，
  分成「本机已装、索引版本更高」（逐条「更新」）与「索引里还没装的包」
  （逐条「安装」）两堆，按钮走 `plugin_pull`。装完在插件列表里和用户导入的包一模一样，
  没有特殊身份；页面上「索引：」那一行显示本次实际用的地址；
- 索引地址可以在「后台参数 → 解析规则」里改（键 `rules.index_url`，类型 `text`，
  默认官方索引；见 §6）——官方地址在墙内常拉不动，不给出镜像位就等于没有更新功能；
- 插件存在 `<share_rules>/plugins/<name>/`：

  - macOS `~/Library/Application Support/HanCast/share_rules/plugins/`
  - Windows `%APPDATA%\HanCast\share_rules\plugins\`
  - Linux `~/.config/hancast/share_rules/plugins/`

- 每条规则有独立开关（落 `plugins/state.json`，重装/重启都保留）；
  「试跑」输入一段粘贴内容，走真实解析管线，直接显示解析到的标题/地址/通道；
- 同名 ZIP 再导一次=覆盖更新（prefs 与规则停用状态保留——覆盖只动 `plugins/<name>/`）；
  删除也只删包目录，`plugins/_cache/<name>/`（`host.readCache/writeCache` 的落点）**不会**跟着清，
  想释放空间得手动删那个缓存目录。

## 6. 官方规则包与那份索引

官方包是「源 + 产物 + 索引」三件套，全在仓库根，不在应用里：

```
rule-packs/
├── <name>/{manifest.json,main.js}    ← 源：hancast-bilibili / hancast-douyin / hancast-template
├── dist/<name>-<version>.zip         ← 产物：tools/build-rule-packs.py 生成
└── index.json                        ← 索引：{"packs":[{name,version,url,sha256,description}]}
```

- **产物靠 main 分支发布**：索引里的 `url` 是
  `https://raw.githubusercontent.com/pingod/HanCast/main/rule-packs/dist/<file>`
  （脚本里 `RAW_BASE` 写死 main 分支——换到别的分支产物就装不上，
  宁可当场炸出来，也不静默产出一份坏索引）；
- zip 用固定时间戳（1980-01-01）与固定条目顺序（`manifest.json` 在前、脚本按名排序），
  外部属性也固定成普通文件位：内容没改 ⇒ sha256 不变 ⇒ `index.json` 不跟着无意义地跳，
  `--check` 才有意义；
- 打包时挡下四种写坏的源：目录名 ≠ `manifest.name`（否则索引里的包名和用户机器上的
  目录名对不上）、`version` 为空、`scripts` 没声明任何脚本、`scripts` 引用不存在的文件；
  包目录里出现**未被 `scripts` 声明的 `.js`** 也当场报错——导入端收得进 zip 却不会进
  执行清单，静默丢包不如不产出；
- `python3 tools/build-rule-packs.py --check` 只比对不写盘，退出码 1 会逐行列出
  「需要重建: dist/…」「需要重建: index.json」「孤儿产物: …」；`--clean` 删掉 dist 里
  源目录已不存在的 zip；
- **索引与包地址**：索引本身允许 http(s)（内网镜像是正当用法），但清单里每个 zip 的
  下载地址必须 https——那是「下载来就要执行里面 JS」的入口。`fetch_index` 直接丢掉
  `name` 不匹配 `^[A-Za-z0-9_-]{1,64}$` 或非 https 的坏条目，一个坏条目不拖垮整页
  检查更新；
- **摘要是硬约束**：`pull` 下载完先比索引给的 sha256，对不上就报「包校验失败
  （sha256 不匹配，可能被劫持或索引过期）」，不落盘。所以改了包里任何字节都必须重跑
  打包脚本并把新产物与索引一起提交；用自己的镜像时也必须照抄官方条目的 sha256；
- 为什么索引地址必须可换（后台参数 `rules.index_url`，登记表里 `params.DEFAULT_RULES_INDEX`
  写死一份，`jsplugins.index_url()` 只读它，别处不再抄一遍）：
  `raw.githubusercontent.com` 在墙内经常拉不动，给不出镜像位就等于没有更新功能；
- 不在官方索引里的包（自己搭的）也能更新：`pull` 在索引查不到它时退回该包
  `manifest.update_url` 自己声明的地址，两者都没有才报错。

## 7. 规则总览：两种来源一处管理

设置 → 解析插件 顶部是一张清单（Tauri command `rule_inventory`），把解析管线里所有
可能的规则来源摊开，各自可控。它返回 `{rules_dir, script_packs, declarative}`——
**只有这两种来源**，单测断言过这个 key 集合，再冒出第三个就说明有人把「内置规则」
偷偷加了回来：

1. **规则包（JS 脚本）**（`script_packs`）—— 用户自己导入的包与从索引装的包完全同列，
   逐条规则开关；没有「内置包」徽章、没有不能删的包（`remove()` 谁都不拒绝），
   manifest 读不出来的坏包也占一格并带 `error` 原因；
2. **声明式规则（JSON 文件）**（`declarative`）—— `share_rules/` 目录里的每个 `.json`，
   显示 hosts/阶段/步数，`rules_dir` 就是清单里给设置页展示的那个目录；
   **写坏的文件也会出现在清单里并标出原因**，而不是静默消失。

优先级只有两档，没有「盖住内置」这回事：

- 包规则的 `priority` 缺省 5，并且被钳在 **4–8**：笔误或坏心的规则既插不了队也垫不到底；
- 声明式规则 `priority` 固定 **5**，与包规则同段；
- 注册表按 `(priority, name)` 排序，同值按规则名决胜；这两档都排在通用正文提取之前
  ——通用提取不是规则对象，而是所有规则都不命中时的兜底。

逐条停用的状态存 `plugins/state.json` 的 `disabled`（键是 `<包名>/<规则 id>`），
进程重启照原样恢复；旧版本用来关内置 Python 规则的 `disabled_builtin` 键在读取 state
时就被丢弃，不再参与任何判定。

## 8. 打包约束（导入器会拒收的包）

| 限制 | 值 |
| ---- | ---- |
| ZIP 体积 / 文件数 / 解压后总大小 / 单文件 | 2MB / 128 / 8MB / 2MB |
| 允许的条目 | 一层目录（可选）下的 `manifest.json` 与 `*.js`，其余拒收 |
| 软链接 / 绝对路径 / `..` / 反斜杠路径 | 拒收 |
| `manifest.name` | `^[A-Za-z0-9_-]{1,64}$` |

## 9. 排错

- 设置页插件卡片显示「加载失败」+ 原因 = 脚本加载就崩了（语法错、registerRule
  缺字段）；某条规则让路的原因看日志（模块前缀 `hancast.media` / `hancast.media.jsplugin`）；
- **不点 GUI 跑真实管线**：`hancast-backend/.venv/bin/python tools/verify-rule-packs-live.py "<链接或口令>" …`
  只把 `ShareResolver` 拎出来配一个假媒体服务器，因此证明的是「规则能否取出可播地址」，
  不含电视端真实播放。判据看输出的 `via`：`<包名>/<规则 id>` ＝ 走了 JS 规则包，
  不带斜杠的规则名 ＝ 走了声明式 JSON 规则，`page`／`direct`／`playlist` ＝ 没有任何规则
  命中、由通用提取兜住（改走本机代理时多一个 `+proxy` 后缀）。
  脚本默认把 repo 根 `rule-packs/dist/` 的官方包当作用户导入的 zip 装进临时目录
  （装之前先比 `index.json` 里的 sha256，产物过期就当场失败），`--no-packs` 只跑目录里
  已有的规则；程序里没有编译进去的站点规则，所以「没装包 ⇒ 什么站点都解析不了」是预期行为。
  加 `--verbose` 打开 sidecar 日志看让路/失败的具体原因，`--rules-dir <dir>` 指定规则目录，
  `--keep` 保留临时目录以便查看插件缓存；
- 现场复现整条管线（含电视视角验证与代理）：`python tools/share_resolve_probe.py --serve --play --mpv "<粘贴内容>"`，
  规则包规则与声明式规则同一条管线，探针自动覆盖；
- 单测参考：`hancast-backend/tests/test_jsplugins.py`（沙箱、导入校验、管线接入、
  规则总览只有两种来源、索引检查更新与 sha256 拒装、`update_url` 回退、包规则优先级钳位）。

## 10. 把一个新规则包发布到官方索引的清单

1. 建目录 `rule-packs/<name>/{manifest.json,main.js}`：`manifest.name` 用
   `hancast-<site>` 小写连字符、且必须等于目录名（打包脚本会比对，否则索引里的包名和
   用户机器上的目录名对不上），`version` 从 `1.0.0` 起（「检查规则包更新」按它决定给不给升级）；
2. 用 `tools/verify-rule-packs-live.py` 拿真实链接跑通，`via` 必须是 `<包名>/<规则 id>`；
   **跑不通的包不要塞进索引**——索引是所有用户点「安装」时看到的默认列表；
3. `python3 tools/build-rule-packs.py` 产出 `dist/<name>-<version>.zip` 并重写
   `index.json`（`name/version/url/sha256/description` 全部取自包目录）；
   改完用 `--check` 确认产物与源同步（退出码 1 会列出要重建的东西）；
4. 提交时**源目录、`dist/` 里的 zip、`index.json` 一起提交**：索引里的 `url` 指向 dist，
   少了 zip 用户点「安装」就是 404；
5. 推到 `main`：`RAW_BASE` 写死 main 分支的 raw 地址，产物不落 main 就装不上；
6. 改了包里任何字节都要**抬 `manifest.version` 并重跑第 3 步**：不抬版本号 ⇒ 索引版本
   不高于本机 ⇒ 永远不提示更新；抬了版本忘了重跑 ⇒ 摘要与产物不符，装包被 sha256 拦下；
7. 应用侧无需改动：清单与更新段都是数据驱动的，新包自动出现在
   「官方索引里还没安装的包」，i18n 也不用动；
8. 产物级验收（`tools/accept-macos-artifact.sh`）断言的是「退役干净」：冻结 sidecar 里不许
   出现 `media/rules/bili.py`、`media/rules/douyin.py`、`media/bili_resolver.py`、
   `rule_plugins`；命令表里不许有 `rule_set_builtin_enabled`；`rule_inventory` 只报两种来源
   且 `script_packs` 里不许出现 `"builtin"` 字段；`plugin_check_updates`、`plugin_pull` 必须已注册。

## 11. 附录：取不到流的站点（2026-10-13/14 实测）

写包前先确认站点给不给匿名流。这三个平台的取证结论是「匿名拿不到播放地址」，
所以官方索引里没有为它们出的包，`docs/examples/` 里也不提供半成品
（表里的「抖音网页」指 `ixigua.com`／www 网页这条路径；索引里的 `hancast-douyin`
走的是 `iesdouyin.com` 分享页内嵌 JSON，不是同一条路）：

| 平台 | 取证 | 结论 |
| ---- | ---- | ---- |
| 西瓜 / 抖音网页 | `https://www.ixigua.com/<id>` 返回 HTTP 200、**72914 字节**、正文只有一个 `$jsvmprt` JS-VM 挑战壳（`<body>` 为空，播放数据要浏览器执行 JS 才生成） | 沙箱里的 QuickJS 跑不了这套 VM 混淆，`page` 阶段规则取不到地址 |
| 微博 | 分享链走 `m.weibo.cn`：接口在无 Cookie 时返回 **HTTP 432** 风控（2026-10-13 真实链接）；换成不存在的 id 才回 200＋`该微博不存在`，说明端点可达但按风控分层 | 无 Cookie 拿不到 `stream_url`；要做必须让用户填 Cookie（prefs），不是纯规则 |
| 快手 | `https://www.kuaishou.com/graphql` 匿名查询返回 **`{"result": 2}`**（需要 `did`/签名头），正文页同样只有引导壳 | 同上：要么带设备指纹，要么放弃 |

共同的坑：**同一链接两次结果可能不同**。抖音分享页曾在短时间窗口里给出过完整
`_ROUTER_DATA`（含 `play_addr`），随后又退回只有壳的版本——所以「我这轮成功过一次」
不能作为把包发进官方索引的依据，判定要在多条真实链接上重复。

完整可参考的示例插件在 [`docs/examples/collect-site/`](examples/collect-site/)。
